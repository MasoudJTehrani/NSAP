All the MIM (man-in-the-middle) evaluation code lives in /home/usi/NSAP/rung2/. Here's the map, organized for your bottom-up review.

The core evaluation — two small files (~240 lines each)
1. rung2/env.py (243 lines) — Rung2Env: the robot "body" ← the true bottom, start here
The AI2-THOR 5.0 environment/executor. Contains: the skill layer (execute: find / pick up / open / close / turn on-off / put / slice), auto-navigation (navigate_to — teleports to a GT pose), check_success (reads THOR metadata), and view_target (for the offline tools). No patch logic here — it's the clean environment.

2. rung2/harness.py (235 lines) — the eval loop / orchestrator ← the entry point
Ties everything together: builds the ESCA planner (make_planner), loads a task file, and run_episode runs the closed loop per condition — injects the patch every frame the target is visible (render_inject), calls planner.act(), executes the action via env, records success + the sg_log (planner text). main() runs the sweep and prints the table. This is where the patch injection + the base/esca/patch conditions (CONDS) live.

The inputs (task definitions)
rung2/gap_tasks_v2.json — the current 8 conditional gap-tasks (what we've been iterating).
rung2/tasks.json — original category/attribute/relation tasks. Plus tasks_pf.json, tasks_pf2.json, gap_tasks.json (earlier variants).
Auxiliary / diagnostic tools (not the main loop)
rung2/flip_rate.py — MLLM-free perception flip-rate (calls GD+SGClip directly, no episode/planner).
rung2/debug_text.py — SG text clean-vs-patched on a single frame.
rung2/disambig.py — the disambiguation experiment (perception-driven executor; bypasses the MLLM).
rung2/mllm_probe.py — does the patch fool gpt-4o-mini's own vision.
